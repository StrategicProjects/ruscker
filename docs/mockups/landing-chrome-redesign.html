Design notes

  • Cluster anatomy: three slots — theme (icon-only) · language (icon + 2-letter badge) · account (icon-only when signed in, "Sign in" text-button when anonymous).
  • Disclosure: the theme and language buttons open small popovers anchored under the cluster. Using native <details>/<summary> keeps it keyboard-accessible with zero JS — the form buttons inside POST to /__set/theme and /__set/locale just like today's footer.
  • Account slot: anonymous viewers get a textual "Sign in" CTA (it's a primary action, not a settings menu). Signed-in viewers get a user-icon that opens a popover with the username, Panel link, Change-password link, and a Sign-out button.
  • Logo: small Ruscker mark (28×28) left of the operator's title. When the operator later configures their own brand mark via landing-customization.logo (future), it slots into this same position.
  • Footer: shrinks to status link + docs link + "powered by Ruscker · v0.1.2" right-aligned. Theme + language pickers leave the footer entirely.

Scope & pages

  • templates/_layout.html — replace footer chrome with the new cluster in the existing templates/landing.html header.
  • templates/landing.html — host the cluster in the existing header row (already has the sign-in affordance from #155, easy to absorb).
  • templates/admin/login.html + setup.html + account_password.html — replace the current bottom-of-card locale row with the same cluster at the top-right of the page (above the card).
  • templates/admin/_layout.html — same cluster top-right of the admin chrome (replaces the footer pickers added in #53).

Open questions

  • Should the theme icon directly cycle on click (one click = next mode) instead of opening a popover? Faster but loses the visible "auto" state. The mockup uses popover for clarity; happy to swap.
  • Language popover shows native names ("English", "Português") with a 2-letter code prefix. Keep that, or just the code, or just the name?
  • Footer still has the "powered by Ruscker" lockup. Should the version number be a click-through to the GitHub release page?
